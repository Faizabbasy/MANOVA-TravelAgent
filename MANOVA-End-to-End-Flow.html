MANOVA — Flow End-to-End

Perjalanan bisnis penuh: dari Lead masuk (publik maupun manual) sampai Project ditutup — 23 langkah Workflow Utama lintas seluruh role (Sales, Account Executive, Management, Project Manager, Operations, Ticketing/Accommodation/Transportation/MICE, Procurement, Finance, Client, Supplier/Vendor), bukan hanya satu modul.

Cakupan: Lead → Qualification → Opportunity → Quotation → Won → Project → Fulfillment → Finance → Closed Sumber: docs/frontend-workflow-map.md, docs/frontend-known-issues.md Status: 22/23 langkah selesai, 1 langkah sebagian (#19)

Ringkasan

Dokumen ini memetakan seluruh perjalanan MANOVA — bukan hanya Client dan Vendor — mengikuti "Workflow Utama" 23 langkah yang menjadi acuan resmi proyek (`docs/frontend-workflow-map.md`, hasil regresi penuh Section 24): Lead → Sales Qualification → Account Executive → Opportunity → Requirement → Product Planning → Quotation → Management Approval → Client Confirmation → Won → Active Client → Project Order → Handover ke Project Manager → Planning → Traveler → Supplier Sourcing → Service Booking → Readiness → On Trip/Event → Changes/Incident → Finance → Completed → Closed.

Client–Vendor Commodity (Vendor publish komoditas, Client pilih/hold/konfirmasi) adalah satu jalur tambahan yang beririsan dengan langkah Traveler Collection–Service Booking, dijelaskan detail di bagian 4 dan tetap punya dokumen sendiri (`docs/MANOVA-Client-Vendor-Commodity-End-to-End-Flow.md` / `.html`) — tidak dihapus, hanya tidak lagi berdiri sendiri sebagai "flow end-to-end" karena ruang lingkupnya memang lebih sempit dari itu.

Jalur Tambahan — Client–Vendor Commodity

Bukan bagian dari 23 langkah Workflow Utama — beririsan dengan #15–#17

Client–Vendor Commodity memberi Client cara lain memenuhi kebutuhan project langsung dari katalog komoditas Vendor — di luar RFQ/Service Order formal (#16) dan booking per-domain Flight/Hotel/Transport/MICE (#17):

Vendor Publish→ Client Katalog→ Requirement→ Matching→ Selection→ Soft Hold→ Confirmation→ Sold

Route: /supplier/commodities, /supplier/commodity-orders (Vendor); /client/project-orders/[id]?tab=commodity, /client/catalog/[requirementId] (Client). Detail penuh 13 skenario happy/alternative path, matriks CRUD, dan known limitations tetap ada di docs/MANOVA-Client-Vendor-Commodity-End-to-End-Flow.md dan MANOVA-Client-Vendor-Commodity-End-to-End-Flow.html — tidak diubah oleh dokumen ini.

Known Gaps

Dilaporkan jujur, bukan disembunyikan — status TIDAK ditulis 100%

Yang masih terbatas

  • Langkah #19 (On Trip / Event) — Sebagian. Status ongoing-trip, run sheet, shift notes, dan 4 modul booking per domain sudah ada, tapi belum ada lifecycle "on-trip" terpadu lintas seluruh domain dalam satu tampilan.
  • Accommodation (HotelBooking) tidak punya flag hasScheduleChange setara Flight/Transport/MICE — gap parity kecil dan kosmetik, tidak memblokir alur Change Request.
  • Project Closed "documents complete" bersifat best-effort — hanya mengecek tidak ada dokumen kedaluwarsa, belum ada daftar dokumen wajib per tipe project untuk dibandingkan.
  • Client–Vendor Commodity punya known limitations sendiri (Archive tidak memperingatkan Selection aktif, belum ada halaman "My Orders" khusus Client, dsb.) — lihat dokumen detailnya.
  • Tidak ada backend/database sungguhan di mana pun sepanjang flow — seluruh state adalah reactive() in-memory.
