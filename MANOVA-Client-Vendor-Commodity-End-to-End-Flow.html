Client–Vendor Commodity — Flow End-to-End

Alur penuh Vendor mempublikasikan komoditas sampai Client memilih, menahan sementara (Soft Hold), dan Vendor mengonfirmasinya menjadi Order terjual — happy path dan alternative path, berdasarkan implementasi aktual (Phase 1–6).

Periode: 31 Jul – 1 Agu 2026 Cakupan: Phase 1–6 (Domain, CRUD, Katalog, Vendor Orders, Regresi) Status validasi: 91/91 test lulus, 0 error typecheck/lint, build sukses

Ringkasan

Fitur Client–Vendor Commodity memungkinkan Vendor mempublikasikan komoditas (kamar, tiket, slot venue, dsb.) yang dapat dicari dan dicocokkan otomatis oleh Client terhadap kebutuhannya, dipilih dan ditahan sementara (Soft Hold), lalu dikonfirmasi Vendor menjadi Order dengan snapshot harga permanen — lengkap dengan ringkasan "Sold Commodities" di sisi Vendor.

Dokumen ini adalah versi visual/HTML dari docs/MANOVA-Client-Vendor-Commodity-End-to-End-Flow.md, dapat diunduh sebagai PDF (tombol di atas) untuk dibagikan ke pihak yang tidak membuka repository langsung.

13 Skenario — Happy Path & Alternative Path

Sesuai instruksi Phase 7 — seluruh happy path dan alternative path didokumentasikan

1. Vendor create dan publish commodity

Selesai

Happy path: /supplier/commodities → "Buat Komoditas" → createCommodityProduct (status draft) → tambah Variant/Availability Slot → "Publish" → updateCommodityProductStatus → otomatis naik ke available/limited via syncCommodityProductAvailabilityStatus.

Alternative path: Publish ditolak bila status bukan draft/suspended — toast error (Phase 6 fix). Harga pokok internal tidak pernah dirender ke Client.

2. Client melihat catalog

Selesai

Happy path: /client/catalog/[requirementId] → getCatalogVisibleCommodities() menyaring HANYA published/available/limited DAN sisa stok > 0.

Alternative path: Tidak ada match sama sekali → EmptyState "No Match". Ada match tapi search filter kosong → EmptyState "Tidak Ada Hasil" terpisah (Phase 6 fix).

3. Client membuat requirement

Selesai

Happy path: /client/project-orders/[id]?tab=commodity → "Tambah Kebutuhan Komoditas" → createCommodityRequirement (status draft).

Alternative path: Edit hanya saat draft, Delete hanya draft/open — ditegakkan di data layer, bukan hanya UI.

4. Matching

Selesai

Happy path: matchCommoditiesForRequirement — rule deterministik (kategori + kuantitas + cakupan tanggal) → tier exact-match/near-match/alternative, dikelompokkan 3 SectionCard.

Alternative path: Kategori berbeda atau availability 0 → no-match, disaring dari hasil (tidak tampil sebagai grup kosong).

5. Client selection

Selesai

Happy path: Dialog pilih Variant + Quantity (dibatasi sisa availability) + Choice Rank (Primary/Secondary/Third) → "Simpan Draft" atau "Ajukan Selection".

Alternative path: Rank/commodity duplikat aktif → hasActiveSelectionWithRank/hasActiveDuplicateSelection menolak dengan toast error, bukan silent no-op.

6. Soft Hold

Selesai

Happy path: submitAndHoldCommoditySelection — availability dicek ulang, heldQuantity naik, holdExpiresAt = H+3 dari tanggal acuan.

Alternative path: Stok habis tepat saat submit → rollback status + toast error. Client dapat membatalkan hold kapan saja (cancelCommoditySelectionHold, stok dikembalikan).

7. Confirmation

Selesai

Happy path: Vendor di /supplier/commodity-orders → "Menunggu Konfirmasi" → "Konfirmasi Order" → confirmCommodityOrderFromSelection: Soft Hold→Confirmed (held→booked) → snapshot Order baru.

Alternative path: Komoditas sudah archived/suspended/expired → ditolak eksplisit (Phase 6 fix). Order duplikat untuk selection yang sama → ditolak.

8. Vendor sold commodity

Selesai

Happy path: isCommodityOrderSold = confirmed/booked/in-service/completed. Status timeline di Order detail + ringkasan "Sold Commodities" (qty, revenue, jumlah order) di Vendor Orders.

Alternative path: Order dibatalkan → langsung tidak lagi dihitung sold; Selection ikut disinkron sehingga Client melihat status yang sama.

9. Hold expired

Selesai

Happy path: sweepExpiredHolds() — sapuan lazy (bukan cron), mengembalikan stok dan mengubah status ke expired. Dipanggil di halaman Client dan Vendor (Phase 6 fix — sebelumnya hanya sisi Client).

Alternative path: Selection yang sudah expired tidak bisa lagi dikonfirmasi.

10. Sold out

Selesai

Happy path: Setiap mutasi Availability memicu syncCommodityProductAvailabilityStatus — sisa stok 0 → sold-out, otomatis hilang dari katalog.

Alternative path: Selection yang sudah Soft Hold SEBELUM produk sold-out (karena selection itu sendiri yang menghabiskan stok) tetap sah dikonfirmasi — diverifikasi eksplisit di test regresi.

11. Commodity archived

Selesai, dengan keterbatasan

Happy path: Vendor "Archive" → updateCommodityProductStatus(id, 'archived') → hilang dari katalog, data historis tetap utuh.

Alternative path (defect Phase 6, sudah diperbaiki): Soft Hold lama pada komoditas yang di-archive sekarang ditolak saat Confirmation. Keterbatasan yang masih ada: aksi Archive sendiri tidak memperingatkan vendor bila masih ada Selection aktif — hanya jalur "menjual" yang dijaga.

12. Availability changed

Selesai

Happy path: updateAvailabilitySlotTotal — setiap perubahan memicu ulang syncCommodityProductAvailabilityStatus, katalog Client selalu konsisten tanpa refresh manual.

Alternative path: Kapasitas baru negatif atau lebih kecil dari bookedQuantity → ditolak, toast error.

13. Permission boundary

Selesai

Happy path: Isolasi Vendor (vendorScopeId) dan Client (clientScopeId) diterapkan di setiap selector data dan setiap halaman (isOwn + RoleAccessState). Client tidak pernah melihat harga pokok/margin Vendor; Order snapshot tidak berubah walau harga produk diedit setelahnya.

Alternative path: Akses ID yang tidak ada/bukan milik sendiri lewat URL langsung → halaman "Tidak Ditemukan" yang aman, tidak pernah crash.

Known Limitations

Belum sepenuhnya lengkap — status TIDAK 100%

  • Archive/Unpublish tidak memperingatkan bila masih ada Selection aktif yang mereferensikan komoditas.
  • Tidak ada log riwayat status Order tersimpan — Status Timeline adalah representasi visual, bukan audit trail bertimestamp.
  • Pembatalan Order setelah Booked/In Service tidak mengembalikan booked quantity ke Availability Slot.
  • Belum ada halaman "My Orders" khusus Client — Client melihat status via tabel Selected Commodities, bukan daftar Order tersendiri (data layer getCommodityOrdersByClient sudah ada, UI belum).
  • Belum tersambung backend/database sungguhan — seluruh state adalah reactive() in-memory.
